## Решение

### Таблица операций чтения

| Коллекция    | Операция чтения                                      | Реплика для чтения | Обоснование                                                                                 |
|--------------|------------------------------------------------------|--------------------|---------------------------------------------------------------------------------------------|
| **products** | Поиск товаров по категории и фильтрам                | secondary          | Данные о категориях и атрибутах меняются редко, устаревание на несколько минут допустимо    |
| **products** | Получение информации о конкретном товаре для покупки | primary            | Критически важна актуальность цены и остатка для предотвращения продажи недоступного товара |
| **products** | Поиск товаров для каталога и навигации               | secondary          | Небольшое устаревание данных приемлемо для отображения каталога                             |
| **orders**   | Просмотр истории заказов пользователя                | secondary          | Исторические данные меняются редко, задержка до 1 минуты допустима                          |
| **orders**   | Проверка текущего статуса заказа                     | primary            | Пользователь должен видеть актуальный статус доставки и обработки заказа                    |
| **orders**   | Отображение деталей заказа для службы поддержки      | secondary          | Для аналитических целей допустимо устаревание данных                                        |
| **carts**    | Получение корзины пользователя при просмотре         | secondary          | Неактуальность на несколько секунд не критична для просмотра                                |
| **carts**    | Проверка корзины перед оформлением заказа            | primary            | Необходима гарантия актуальности данных для предотвращения конфликтов                       |

### Допустимая задержка репликации

- **products (secondary)**: до 5 минут - данные категорий и описаний меняются редко
- **orders (secondary)**: до 30 секунд - исторические данные стабильны
- **carts (secondary)**: до 10 секунд - баланс между производительностью и актуальностью
- **Все primary операции**: максимальная актуальность, задержка < 1 секунды

### Обоснование выбора

#### Требования к консистентности

- **Строгая консистентность** требуется для операций, влияющих на финансовые транзакции (проверка цен, остатков,
  статусов заказов)
- **Ослабленная консистентность** допустима для операций отображения и аналитики

#### Частота обновлений

- **Высокая частота**: цены, остатки, статусы заказов → primary реплика
- **Низкая частота**: категории, исторические данные, описания товаров → secondary реплика

#### Бизнес-логика

- **Риск финансовых потерь**: операции с деньгами требуют primary
- **Пользовательский опыт**: актуальность статусов заказов критична для доверия
- **Производительность**: чтение с secondary разгружает primary для операций записи
